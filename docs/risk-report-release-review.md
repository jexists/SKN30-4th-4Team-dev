# 위험보고서(Risk Report) 출시 준비 리뷰

> 검토일: 2026-07-29  
> 검토 범위: 현재 구현된 프런트엔드 화면, 업로드 흐름, 분석 API, 데이터 모델 및 테스트  
> 관점: Product Manager, UX Lead, Frontend Tech Lead, 부동산 계약 전문가

현재 상태는 **“업로드 → OCR/AI 분석 → 결과 표시”의 기술 연결은 되어 있지만, 실제 계약 의사결정에 사용하는 출시 버전으로는 보류가 필요한 상태**다.

가장 큰 출시 차단 이슈는 다음 6가지다.

1. 로그인 상태에서 결과 없이 `/risk-report`에 직접 접근하거나 새로고침하면 가짜 점수 72점과 샘플 위험 조항이 표시된다.
2. 보고서가 저장되지 않고 React Router의 일회성 `location.state`로만 전달된다.
3. 등기부등본·계약서·건축물대장 3개를 필수로 받지만 결과는 문서별 분석 없이 하나의 텍스트로 합쳐진다.
4. 안전 점수가 프런트엔드 임의 공식으로 계산되어, 필수 정보가 없어도 위험 항목이 0개면 100점 “안전”이 된다.
5. “PDF 다운로드”는 리포트 PDF가 아니라 첫 번째 업로드 문서의 마스킹본이다. 현재 업로드 순서상 첫 번째는 등기부등본인데 파일명은 `masked-contract.pdf`가 된다.
6. 위험 근거 문서·페이지·법률 조항·신뢰도·분석 버전이 없어 결과를 검증할 수 없다.

검토 기준은 현재 [위험보고서 화면](../frontend/src/pages/RiskReport/RiskReport.tsx), [업로드 흐름](../frontend/src/pages/Analyze/Analyze.tsx), [분석 API](../backend/app/api/routes/documents.py), [분석 데이터 모델](../backend/app/schemas/document.py)이다.

프런트 빌드는 성공했고 28개 테스트 파일, 165개 테스트가 통과했지만 Risk Report 전용 테스트는 없다.

### 업로드 → 분석 흐름

- 등기부등본, 임대차계약서, 건축물대장 3개 슬롯이 있다.
- 각 슬롯은 파일 선택과 드래그 앤 드롭을 지원한다.
- 기존 파일 변경 및 삭제가 가능하다.
- 슬롯별 한 개 파일만 유지한다.
- PDF, PNG, JPG, JPEG만 허용한다.
- 파일당 20MB를 초과하면 프런트에서 거부한다.
- 확장자 오류, 크기 초과, 중복 파일을 토스트로 알린다.
- 업로드 완료 개수를 `N/3`으로 표시한다.
- 세 문서가 모두 있어야 “OCR 진단하기” 버튼이 활성화된다.
- 분석 중 버튼을 비활성화하고 “진단 중...”으로 표시한다.
- API 성공 시 성공 토스트 후 위험보고서로 이동한다.
- 분석 실패 시 공통 오류 모달을 표시하고 업로드 파일은 유지된다.

### 백엔드 분석 기능

- 최대 3개 문서를 순차적으로 OCR 처리한다.
- 문서별 개인정보 마스킹과 안전성 검증을 수행한다.
- 개인정보가 남아 있으면 LLM 전송 전에 전체 분석을 중단한다.
- 문서별 마스킹 수, 마스킹 범위, 검토 필요 여부를 집계한다.
- 모든 OCR 텍스트를 하나로 합쳐 구조화된 AI 분석을 요청한다.
- AI 결과는 요약, 계약 조건, 위험 목록, 누락 정보 구조로 반환된다.
- OpenAI 모델이 없을 때 로컬 규칙 기반 분석을 사용할 수 있다.
- OCR 서버 연결 실패·타임아웃·잘못된 응답과 AI 실패를 구분한다.
- 빈 파일, 지원하지 않는 확장자, 파일 크기, 문서 글자 수를 검증한다.
- 문서별 마스킹 PDF를 `documents` 배열로 반환하는 백엔드 구조가 존재한다.

### 구현된 것처럼 보이지만 실제 기능은 아닌 항목

- “위치 정보 분석”은 정적 배지와 배경만 있고 분석 데이터나 API가 없다.
- “전세가율/재무 건전성”처럼 보이는 막대는 매매가·시세·선순위 채권과 무관한 단순 위험 점수 막대다.
- 마이페이지의 최근 진단 이력은 하드코딩된 샘플이다.
- 진단 이력 상세 링크가 이동하는 `/analyze/:id` 화면은 `<h1>진단 결과 화면</h1>`만 있는 플레이스홀더다.
- 헤더의 최근 기록·알림 버튼은 클릭 동작이 없다.
- DB에는 `contract`, `contract_analysis` 테이블 정의가 있지만 현재 분석 API와 연결되지 않았다.
- 업로드 화면의 “실거래가와 대법원 판례 데이터를 대조한다”는 문구는 현재 문서 분석 엔드포인트에서 확인되지 않는다. 이 엔드포인트는 OCR 텍스트와 LLM/로컬 규칙만 사용한다.
- 일반 법적 근거 페이지는 있지만 개별 위험 카드와 연결된 법률 근거는 없다.

### P1 — 출시 직후 필수 고도화

- 위험 등급별 HIGH/MEDIUM/LOW 개수와 필터를 제공한다.
- HIGH와 MEDIUM을 동일한 주황색 상태로 합치지 않고 의미를 분리한다.
- 각 위험을 `확인 전/협상 중/수정 완료/전문가 확인 필요`로 관리한다.
- 위험별 권장 특약 문구와 수정 전·후 비교를 제공한다.
- 계약 전·계약 당일·잔금일·입주 후 체크리스트를 분리한다.
- 소유자 신원 및 대리계약 위임장 확인 항목을 추가한다.
- 근저당·압류·가압류·가처분·신탁·전세권·임차권등기 등 권리 유형을 구조화한다.
- 채권최고액, 선순위 보증금, 예상 배당 가능 금액을 별도 표시한다.
- 위반건축물, 용도, 주용도·실제 사용 불일치, 동·호수 존재 여부를 분석한다.
- 보증보험은 단순 “확인”이 아니라 가입 가능성, 불가 사유, 추가 필요 서류를 안내한다.
- 계약 금액을 문자열이 아닌 원화 숫자와 OCR 원문으로 함께 저장한다.
- 날짜를 구조화하고 계약기간 역전·비정상 기간을 검증한다.
- 보고서 생성 시각, 분석 모델, 규칙 버전, 법령 기준일을 표시한다.
- 보고서 재분석과 이전 버전 비교를 제공한다.
- 사용자가 OCR 오인식 내용을 직접 수정하고 다시 분석할 수 있게 한다.
- 공유·다운로드·재분석 성공 및 실패 토스트를 제공한다.
- “복사됨”, “공유 취소”, “권한 거부”를 구분한다.
- 분석 완료 알림을 실제 알림 데이터와 연결한다.
- 사용자 피드백과 오탐·미탐 신고 기능을 추가한다.
- 전문가 검토가 필요한 위험을 별도 큐로 분류한다.

### 업로드 → 분석 → 보고서 UX에서 막히는 지점

1. 비로그인 사용자는 먼저 로그인해야 하지만 업로드 시작 전 기대 시간이나 준비물 안내가 충분하지 않다.
2. UI는 세 문서를 모두 강제하지만 API는 한 문서도 처리할 수 있어 정책이 충돌한다.
3. 계약서만 가진 사용자는 분석을 아예 시작할 수 없다.
4. 파일 확장자만 맞으면 잘못된 문서를 잘못된 슬롯에 올려도 진행된다.
5. 이미지 미리보기, 페이지 수, 해상도, 방향, 누락 페이지 검증이 없다.
6. “OCR 진단하기”라는 버튼명으로는 이후 AI 종합 분석까지 오래 걸릴 수 있다는 사실을 알기 어렵다.
7. 단계별 진행률과 예상 대기시간이 없어 멈춘 것으로 오해할 수 있다.
8. 실패 문서는 `2번째 서류`처럼 순서로만 안내되며 문서명·실패 단계가 충분히 명확하지 않다.
9. 성공 직후 보고서로 이동해 성공 토스트를 인지하지 못할 수 있다.
10. 뒤로가기로 업로드 화면에 돌아오면 선택 파일이 모두 사라진다.
11. 보고서 새로고침 시 실제 결과가 사라지고 샘플 결과가 나타난다.
12. AI 상담으로 이동하면 사용자가 보고서 내용을 다시 설명해야 한다.
13. PDF 버튼은 사용자가 기대하는 보고서가 아닌 첫 번째 문서 마스킹본이다.
14. 공유 버튼은 링크가 아니라 요약 문장만 공유한다.
15. “안전” 점수가 무엇을 의미하고 무엇을 확인하지 못했는지 설명하지 않는다.

## 개발자가 놓치기 쉬운 부분

### 데이터·판정 의미

- 위험이 0개라는 것과 안전하다는 것을 동일하게 취급하면 안 된다.
- OCR 실패로 위험을 찾지 못한 경우와 실제 위험이 없는 경우를 구분해야 한다.
- `missing_information`이 하나라도 핵심 항목이면 점수 상한 또는 판정 불가 정책이 필요하다.
- 일부 문서만 오래된 경우 보고서 전체의 최신성 상태를 별도로 계산해야 한다.
- 동일 위험이 여러 문서에서 발견된 경우 병합 기준이 필요하다.
- 서로 다른 문서가 충돌할 때 어느 값을 계약 조건에 표시할지 정해야 한다.
- LOW가 “낮은 위험”인지 “보호 조항 발견”인지 의미를 통일해야 한다.
- 위험 건수만으로 계산하면 한 개의 치명적 위험과 여러 개의 경미한 위험을 적절히 비교할 수 없다.
- 한 위험에 복수 법률 근거와 복수 권장 행동이 필요할 수 있다.
- AI 모델과 로컬 규칙 분석을 동일한 신뢰도로 표시하면 안 된다.
