# 폴더·파일 구조 안내

이 문서는 SKN30-4th-4Team-dev 레포의 폴더/파일 구조 지도입니다.
"어디에 뭘 두는지"를 처음 온 팀원도 빠르게 파악할 수 있게 정리했습니다.

## 전체 구조 (한눈에 보기)

```
SKN30-4th-4Team-dev/
├── backend/        # FastAPI 서버 (uv, Python 3.12)
├── frontend/       # React 웹 (Vite, TypeScript)
├── data/           # 수집한 데이터 (원본/가공)
├── docs/           # 문서 (PRD, 아키텍처, 이 문서 등)
├── final/          # 산출물 (발표자료, 보고서, 데모)
├── .claude/           # Claude Code용 명령어 모음
├── .coderabbit.yaml   # 코드리뷰 자동화 설정
├── docker-compose.yml # 백+프론트 한 번에 실행 (선택)
├── .gitignore         # Git 추적 제외 목록
├── .gitattributes     # 줄바꿈 정규화 (Mac/Windows 호환)
├── README.md          # 프로젝트 소개·실행법
└── CLAUDE.md          # Claude Code 공통 규칙 (backend/·frontend/에 각각 CLAUDE.md 추가)
```

## 최상위 폴더 — 무엇을 어디에?

| 폴더 | 역할 | 여기에 두는 것 |
|------|------|----------------|
| `backend/` | API 서버 | FastAPI 코드, DB 모델, 서버 테스트 |
| `frontend/` | 웹 화면 | React 컴포넌트, 페이지, 스타일 |
| `data/` | 데이터 저장 | 크롤링/수집 원본, 전처리한 데이터 |
| `docs/` | 문서 | 기획서(PRD), 아키텍처, 회의/결정 기록 |
| `final/` | 최종 산출물 | 발표 PPT, 보고서, 데모 영상/링크 |

## backend/ 상세 (FastAPI)

```
backend/
├── app/
│   ├── main.py          # 서버 진입점 (앱 생성, 라우터·CORS·에러핸들러·로깅 등록)
│   ├── api/             # 엔드포인트(routes/) + 공통 의존성(deps.py: get_current_user)
│   ├── core/            # 공통 코어 (config 설정 · logging · exceptions · security JWT검증)
│   ├── db/              # DB 연결 (Supabase Postgres)
│   ├── models/          # ★ ERD = DB 테이블/관계 (ORM 모델)
│   ├── schemas/         # API 입출력 형태 (Pydantic 검증 모델)
│   ├── services/        # 비즈니스 로직
│   │   ├── ingestion/   # 청킹·임베딩·색인 (오프라인+런타임 공유)
│   │   └── retrieval/   # 런타임 검색 (질의 임베딩+유사도)
│   ├── agent/           # LangGraph 에이전트 (state·prompts·model·nodes·graph)
│   └── tools/           # 에이전트가 호출하는 툴 (base·retrieval_tool)
├── pipeline/            # 오프라인 배치 색인 러너 (data/ → Supabase)
├── tests/               # 백엔드 테스트
├── pyproject.toml       # 의존성·프로젝트 정의 (uv가 사용)
├── .python-version      # 3.12
├── Dockerfile           # 컨테이너 이미지 (선택 실행용)
└── .env.example         # 환경변수 예시 (복사해서 .env로)
```

**핵심 구분 (자주 헷갈림):**
- `models/` = **ERD**. DB에 실제로 저장되는 테이블과 관계. (ORM)
- `schemas/` = **API 계약**. 요청/응답 JSON의 형태 검증. (Pydantic)
- 둘은 필드가 비슷해도 역할이 다릅니다. ERD 그리는 건 `models/`에서.
- `services/ingestion/` = 청킹·임베딩 **로직**(오프라인·런타임 공유), `pipeline/` = 그걸 돌리는 **배치 실행기**.
- DB는 **Supabase**(Postgres + pgvector) 하나로 관계형 데이터와 벡터를 함께 저장. (pgvector = Postgres 확장, Supabase = 그 Postgres 호스팅)

## frontend/ 상세 (React + Vite + TypeScript)

```
frontend/
├── src/
│   ├── main.tsx         # React 진입점 (라우터 + 전역 SCSS)
│   ├── App.tsx          # 공통 레이아웃 (SiteHeader + 페이지 자리 + 하단 연결표시)
│   ├── routes.tsx       # URL ↔ 페이지 매핑
│   ├── pages/           # 화면별 스텁 (화면 이름 텍스트만: Home, Analyze, Chat, ...)
│   ├── components/      # 재사용 컴포넌트 (SiteHeader, HealthStatus, ...)
│   ├── hooks/           # 커스텀 훅 (useHealth.ts)
│   ├── api/             # 백엔드 호출 래퍼 (client.ts)
│   ├── types/           # 공용 타입 (api.ts)
│   └── styles/          # 전역 SCSS (main.scss, _variables.scss)
├── index.html           # HTML 껍데기
├── package.json         # 의존성·스크립트 (npm이 사용)
├── vite.config.ts       # 개발 서버 설정 (/api → 백엔드 프록시)
├── tsconfig.json        # TypeScript 설정
├── Dockerfile           # 빌드 → nginx 서빙 (선택 실행용)
├── nginx.conf           # SPA 라우팅 설정
└── .env.example         # VITE_API_BASE_URL 등
```

> **프론트 명명 규칙**: 컴포넌트·페이지와 그 폴더는 대문자 시작(PascalCase) — `HealthStatus/HealthStatus.tsx`. 훅·유틸·api는 소문자(camelCase) — `useHealth.ts`, `client.ts`. 컴포넌트 하나 = 폴더 하나, 안에 `.tsx`(코드) + (스타일 생기면) `.module.scss`.

## 화면 (사이트맵)

디자인 전, URL과 스텁만 먼저 연결한 상태입니다. **각 화면은 이름 텍스트 한 줄만 보입니다**(예: "로그인 화면"). 각 화면은 `src/pages/`의 폴더 하나에 대응합니다.

| URL | 화면 | 설명 |
|-----|------|------|
| `/` | Home | 서비스 소개·시작 |
| `/analyze` | Analyze | 등기부·계약서 업로드·진단 시작 |
| `/analyze/:id` | AnalyzeResult | 진단 결과 (북마크 가능한 URL) |
| `/chat` · `/chat/:id` | Chat | 새 상담 / 지난 대화 이어보기 |
| `/login` | Login | 소셜(SNS) 로그인 |
| `/onboarding` | Onboarding | 최초 로그인 시 약관·개인정보 동의 (신규만) |
| `/mypage` | MyPage | 마이페이지 (내 기록 포함) |
| `/terms` · `/privacy` | Terms·Privacy | 이용약관·개인정보 처리방침 (전문) |

화면 추가·변경은 `src/pages/`에 폴더를 만들고 `src/routes.tsx`에 한 줄 등록하면 됩니다.

## 실행 방법 (Mac·Windows 동일)

**백엔드**
```
cd backend
uv sync
uv run uvicorn app.main:app --reload   # → http://localhost:8000
```

**프론트**
```
cd frontend
npm install
npm run dev                            # → http://localhost:5173
```

**Docker로 한 번에 (선택)**
```
docker compose up --build              # 백+프론트 동시 실행
```

## 자주 묻는 질문

| 무엇을 | 어디에 |
|--------|--------|
| ERD 설계(문서) | `docs/ERD.md` |
| ERD(DB 테이블) 코드 | `backend/app/models/` (설계 확정 후 작성) |
| API 요청/응답 형태 | `backend/app/schemas/` |
| 표준 응답 봉투 | `backend/app/schemas/common.py` (ApiResponse) ↔ `frontend/src/types/api.ts` |
| API 주소(엔드포인트) 추가 | `backend/app/api/routes/` |
| 청킹·임베딩·검색 로직 | `backend/app/services/` (ingestion·retrieval, 추후) |
| 에이전트(LangGraph)·툴 | `backend/app/agent/` · `backend/app/tools/` (추후) |
| 오프라인 색인 배치 실행 | `backend/pipeline/` |
| 벡터·관계형 데이터 저장 | Supabase (Postgres + pgvector) |
| 로그인 사용자 확인(인증) | `backend/app/api/deps.py`의 `get_current_user` (Supabase JWT 검증) |
| 공통 설정·로깅·에러 | `backend/app/core/` (config·logging·exceptions·security) |
| 테스트 작성 | 백엔드 `backend/tests/` (pytest), 프론트 컴포넌트 옆 `*.test.tsx` (Vitest) |
| 화면(페이지) 추가 | `frontend/src/pages/` + `frontend/src/routes.tsx` 등록 |
| 재사용 컴포넌트 | `frontend/src/components/` |
| 컴포넌트 스타일(SCSS) | 컴포넌트 옆 `*.module.scss` (전역은 `frontend/src/styles/`) |
| 백엔드 호출 로직 | `frontend/src/hooks/` + `frontend/src/api/` |
| 환경변수·설정 | `backend/app/core/config.py` + `.env` |
| 수집한 원본 데이터 | `data/raw/` |
| 전처리한 데이터 | `data/processed/` |
| 기획서(PRD) | `docs/PRD.md` |
| 팀 규칙(컨벤션) | `docs/conventions.md` |
| 실행·첫 설정 방법 | `docs/setup.md` (각 폴더 README에도 요약) |
| 결정·할 일 정리 | `docs/스캐폴딩_계획.md` |
| 발표자료·보고서 | `final/` |
