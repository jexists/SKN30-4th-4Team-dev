# HomeShield 요구사항 정의서(SRS)

- 문서 버전: 1.0
- 작성일: 2026-07-30
- 문서 목적: HomeShield 서비스의 기능 범위, 사용자 동작, 시스템 처리, 예외 처리, 우선순위 및 개발 상태를 정의한다.
- 적용 범위: 사용자 인증, 계약서 업로드, OCR, AI 계약 분석, 위험보고서, AI 채팅, 알림, 마이페이지, 고객지원 및 운영 관리
- 개발 상태
  - 완료: 요구사항에 정의된 주요 기능과 예외 처리가 제공되는 상태
  - 일부 구현: 주요 기능은 제공되지만 보완 개발 또는 운영 정책 정리가 필요한 상태
  - 미구현: 향후 개발 범위에 포함된 상태

### 1.2 사용자 흐름

1. 회원 인증
   - 이메일: 로그인 또는 회원가입 → 필요 시 이메일 인증 → 보호 화면 진입
   - 카카오: OAuth 콜백 → 기존 회원은 로그인, 신규 사용자는 약관 동의 후 회원 생성
   - 보호 화면 접근 시 비로그인 사용자는 원래 경로를 보존한 채 로그인 화면으로 이동한다.
2. 계약 진단
   - 사용자가 계약서·등기부등본·건축물대장 슬롯에 파일을 추가한다.
   - 형식·용량·개수·중복을 검사한 뒤 분석 작업을 접수한다.
   - 백엔드가 비공개 저장소에 임시 저장하고 OCR 워커, 개인정보 비식별화, AI 분석을 순차 수행한다.
   - 알림 폴링으로 완료를 감지하고 위험보고서로 이동한다.
3. 위험보고서
   - 사용자가 목록에서 완료된 분석을 선택한다.
   - 시스템이 요약, 추출 계약 조건, 위험 항목, 권고, 주소 지도를 표시한다.
   - 제목 수정, 삭제, 브라우저 인쇄, AI 상담 이동을 제공한다.
4. AI 채팅
   - 사용자가 새 대화방을 만들거나 기존 방을 선택해 질문한다.
   - 시스템이 법률 벡터 검색과 LLM 생성을 수행하고 대화를 저장한다.
   - 계약서를 첨부하면 별도 분석 작업을 생성하고 완료 결과의 정제 텍스트 일부를 이후 질문에 포함한다.
5. 알림·마이페이지
   - 분석 시작·완료·실패 알림을 폴링으로 수신한다.
   - 프로필, 최근 사용 이력, 비밀번호, 브라우저 알림 설정을 관리한다.
   - 탈퇴 시 계정을 소프트 삭제하고 세션을 회수하지만 관련 데이터는 즉시 삭제하지 않는다.

### 1.3 기능 영역별 개발 현황

| 영역 | 구현된 내용 | 일부 구현 또는 미구현 내용 |
|---|---|---|
| 화면(UI) | 공개·보호 라우트, 반응형 헤더, 주요 업무 화면, 로딩·빈 상태·오류 상태 | 라이브 시세·등기·사기 사례 UI의 실제 데이터 연동 없음, 고객지원 검색·문의 무동작 |
| API | 표준 응답 봉투, 인증·회원, 분석, 채팅 이력, 알림, OCR 상태 API | 개발용 `/hello` 잔존, 분석 취소·비밀번호 재설정·관리자·피드백·출처 API 없음 |
| DB | 회원·프로필·동의·로그인 이력·채팅·알림·분석 작업·결과 모델 | 계약 분석 모델과 RAG 저장 구조의 통합 필요 |
| OCR | PDF·이미지 처리, PaddleOCR-VL, Tesseract 대체, 개인정보 탐지·마스킹·재검사 | 한국어 정밀 좌표 품질 검증 부족, API 키가 선택 사항, 검토 필요 결과를 화면에 표시하지 않음 |
| AI 분석 | 구조화 계약 조건·위험·권고 생성, 로컬 규칙 기반 대체 분석 | 계약 분석 자체에는 RAG·판례·실거래·등기 조회가 연결되지 않음 |
| 위험보고서 | 이력·상세·진행률·위험 항목·권고·지도·제목·삭제 | 점수는 프런트 규칙식, PDF는 인쇄, 누락 정보·비식별 검토 결과 미표시, 실제 LTV·시세 없음 |
| 채팅 | 다중 대화방, 이력, 커서 페이지네이션, RAG 그래프, 첨부 분석 | 응답 스트리밍·중단·구조화 출처·피드백 및 운영용 색인 파이프라인 추가 필요 |
| 파일 업로드 | 다중 파일, 허용 확장자·20MB·10개·중복 검증, 비공개 임시 저장 | 서버가 UI의 3종 문서 유형을 구분·검증하지 않음. 장애 시 고아 파일 정리 배치 없음 |
| 알림 | 환영·분석 시작·완료·실패, 읽음·삭제·필터·배지·브라우저 알림 | Web Push·서비스 워커 없음. 사용자 설정은 인앱 생성이 아니라 브라우저 표시만 제어 |
| 사용자 기능 | 프로필, 닉네임, 아바타, 이메일 비밀번호 변경, 최근 이력, 탈퇴 | 비밀번호 찾기 없음. 3일 후 완전 삭제 배치 없음. 구독·결제·회원 등급 기능 없음 |
| 관리자 | 없음 | 화면, 역할, API, 감사·운영 도구가 구현되어 있지 않음 |

### 1.4 API 구성 및 개발 범위

| API 그룹 | 제공 기능 | 개발 상태 |
|---|---|---|
| 상태 | `GET /api/v1/health`, `GET /api/v1/hello`, `GET /api/v1/ocr-health` | 구현. `hello`는 개발용 |
| 인증·가입 | 카카오 가입 여부 확인, 카카오 로그인 판정, 미완료 가입 정리, 회원가입 완료 | 구현 |
| 내 정보 | `GET/PATCH /api/v1/me`, 알림 설정, 아바타, 회원 탈퇴 | 구현. 탈퇴는 소프트 삭제 |
| 분석 | `POST/GET /api/v1/analyses`, 상세, 제목 수정, 삭제 | 구현. 취소 API 없음 |
| 채팅 생성 | `POST /api/v1/chat` | 구현. 비스트리밍 단건 응답 |
| 채팅 이력 | 대화방 목록·생성·제목·삭제, 메시지 목록·저장, 분석 결과 첨부·해제 | 구현 |
| 알림 | 목록, 안 읽은 수, 읽음, 삭제 | 구현 |
| OCR 워커 | 상태, 마스킹 결과 생성, 분석용 정제 텍스트 생성 | 구현 |
| 추가 개발 API | 비밀번호 재설정, 분석 취소, 채팅 스트리밍·중단, 출처·피드백, 고객문의, 관리자 | 미구현 |

| 회원 | `app_user`, `profile`, `user_agreement`, `login_history` | 사용. 이메일 로그인 이력 기록은 연결되지 않음 |

| 마이그레이션 | SQL 스키마 관리 | 버전 마이그레이션 체계 추가 필요 |

## 2. 요구사항 정의서

|----|------|------------|----------|----------|------|

| REQ-005 | 공통 | 약관과 법적 안내를 열람할 수 있어야 한다. | 사용자는 이용약관, 개인정보처리방침, 법적 근거 페이지를 인증 없이 열람한다. 시스템은 저장된 정적 콘텐츠를 표시한다.<br>개발 상태: 완료 | 필수 | 법무 검수 필요 |

| 순위 | 대상 | 선정 이유 |
|---:|---|---|
| 1 | 회원 탈퇴 정책 정합화 및 완전 삭제 배치 | 개인정보 처리 안내, 접근 차단, 유예 기간, 완전 삭제 시점을 하나의 정책으로 일치시켜야 한다. |
| 2 | OCR 정밀 마스킹 검증과 검토 필요 결과 표시 | 개인정보가 외부 LLM으로 전달되는 경계이므로 출시 전 실문서 품질 검증과 사용자 고지가 필요하다. |
| 3 | 근거 없는 챗봇 답변 차단과 구조화 출처 | 법률 영역에서 빈 검색 결과로 생성이 계속되면 환각을 사용자가 검증하기 어렵다. |
| 4 | 운영용 RAG 색인 파이프라인과 스키마 통합 | 안정적인 법률 답변을 위해 재현 가능한 적재 절차, 문서 버전, 단일 검색 스키마가 필요하다. |
| 5 | 서비스 소개 문구와 개발 범위 정합화 | 등기·시세·판례 비교·프리미엄·상담 범위는 실제 제공 기능과 출시 계획에 맞게 안내해야 한다. |
| 6 | 계약 분석에 법률 근거 연결 | 계약 위험 항목마다 관련 법령·판례·분쟁 사례를 연결해 분석 결과의 설명 가능성을 높여야 한다. |
| 7 | 보고서의 누락 정보·비식별 상태·점수 근거 제공 | 사용자가 보고서의 한계와 추가 확인 항목을 이해할 수 있도록 안전 관련 정보를 함께 제공해야 한다. |
| 8 | 비밀번호 찾기·재설정 | 이메일 회원이 계정 접근을 복구할 경로가 없다. |
| 9 | DB 마이그레이션 및 계약·RAG 모델 정리 | 환경 간 스키마 불일치와 향후 배포 실패 가능성을 낮춰야 한다. |
| 10 | 외부 서비스 포함 E2E·보안 테스트 | OCR 모델, OpenAI, PostgreSQL, Storage, OAuth, 브라우저 알림까지 연결한 실제 흐름 검증이 필요하다. |
