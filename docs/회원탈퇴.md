# 회원 탈퇴 (Soft Delete)

> 관련 코드: `backend/app/repositories/auth.py` · `backend/app/services/auth.py` ·
> `backend/app/api/routes/me.py` · `frontend/src/pages/MyPage/MyPage.tsx`

## 지금 구현된 것 — Soft Delete 만

회원 탈퇴는 **행을 지우지 않는다.** `app_user` 에 표시만 남긴다.

| 컬럼 | 타입 | 의미 |
|---|---|---|
| `is_deleted` | `boolean NOT NULL DEFAULT false` | 탈퇴 여부 |
| `deleted_at` | `timestamptz NULL` | 탈퇴 시각 (완전 삭제 배치의 기준점) |

지우지 않는 이유는 **채팅·계약서 등 사용자 데이터가 그대로 남아 있기 때문**이다.
계정 행만 먼저 지우면 FK 가 CASCADE 로 데이터까지 함께 날리거나, 주인 없는 데이터가 된다.
지금은 계정만 잠그고 데이터는 유지한다.

### 탈퇴 시 일어나는 일 (`DELETE /api/v1/me`)

1. `app_user.is_deleted = true`
2. `app_user.deleted_at = now()`
3. `auth.refresh_tokens` · `auth.sessions` 에서 해당 사용자 레코드 삭제 (Refresh Token 폐기)
4. 프론트는 로그아웃 후 `/login` 으로 전체 새로고침 이동

채팅·계약서·알림 등 **사용자 데이터는 건드리지 않는다.**

### 탈퇴 회원이 막히는 지점

Supabase `auth.users` 행은 남으므로 **카카오 OAuth 자체는 계속 성공한다.** 차단은 백엔드가 만든다.

| 경로 | 결과 |
|---|---|
| `POST /api/v1/auth/kakao/login` | 403 `탈퇴한 계정` |
| `GET /api/v1/auth/registration` | 403 `탈퇴한 계정` (가입 화면으로 보내지 않는다) |
| `POST /api/v1/auth/signup` | 403 `탈퇴한 계정` (같은 카카오 계정으로 재가입 불가) |
| `GET`·`DELETE /api/v1/me` | 403 `탈퇴한 계정` |
| `RequireMember` 가 붙은 모든 회원 API (채팅 등) | 403 `탈퇴한 계정` |

판정은 `AuthRepository` 한 곳에 모여 있다 — `is_registered()` / `get_active_app_user()` /
`is_withdrawn()`. **`db.get(AppUser, ...)` 를 직접 부르지 말고 이 메서드들을 쓴다.**
`_is_withdrawn()` 은 `is_deleted` 와 `deleted_at` 을 모두 보므로, `is_deleted` 도입 전에
`deleted_at` 만 찍힌 행도 탈퇴로 취급된다.

프론트에서는 다른 탭·기기에 남아 있던 세션이 403 을 받으면 `RequireAuth` 가 로그아웃시킨다
(액세스 토큰 JWT 는 만료 전까지 서명이 유효하므로, Refresh Token 폐기만으로는 즉시 끊기지 않는다).
