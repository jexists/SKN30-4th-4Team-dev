# HomeShield 제품 요구사항 정의서(PRD)

> 계약 전에는 놓치기 쉬운 위험을 확인하고, 계약 후에는 법적 근거와 대응 방향을 찾을 수 있도록 돕는 전·월세 분쟁 팩트체커

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | HomeShield |
| 서비스명 | 전·월세 분쟁 팩트체커 |
| 프로젝트 구분 | SKN30 3차 프로젝트 고도화 |
| 문서 버전 | v1.0 |
| 작성일 | 2026-07-30 |
| 핵심 사용자 | 전·월세 계약 경험이 적은 사회초년생·청년 임차인, 임대차 분쟁을 겪는 임차인 |
| 핵심 가치 | 계약서 위험 진단, 근거 기반 AI 상담, 개인정보 보호, 분석·상담 이력 관리 |

우리 팀은 3차 프로젝트에서 만든 Streamlit 기반 전·월세 분쟁 상담 프로토타입을 실제 사용 흐름을 갖춘 웹 서비스로 발전시키는 것을 이번 프로젝트의 목표로 삼았다. 3차 프로젝트의 핵심 아이디어였던 “계약 전 위험 예방과 계약 후 분쟁 상담의 연결”은 유지하고, 사용자 인증, 비동기 문서 분석, 개인정보 비식별화, 리스크 리포트, 대화 이력과 알림 기능을 추가해 HomeShield로 고도화했다.

---

## 1. 프로젝트 개요

HomeShield는 임차인이 전·월세 계약서를 직접 검토하기 어려운 문제에서 출발한 서비스다. 사용자가 임대차계약서와 관련 서류를 업로드하면 OCR로 내용을 읽고 개인정보를 비식별화한 뒤, 주요 계약 조건과 위험 조항을 분석해 리포트로 제공한다. 계약 이후 발생하는 보증금 반환, 수리비, 원상복구, 계약 갱신 등의 질문은 법령·판례·공공 가이드를 검색하는 RAG 챗봇을 통해 확인할 수 있다.

우리 팀이 만들고자 한 것은 계약의 안전을 대신 보장하는 서비스가 아니라, 사용자가 계약서를 읽고 질문하고 다음 행동을 결정하는 데 필요한 정보를 더 쉽게 얻을 수 있는 도구다.

### 제품 한 문장

> “내 계약서에서 무엇을 확인해야 하는지 알려주고, 문제가 생겼을 때 어떤 근거를 찾아봐야 하는지 안내하는 세입자용 AI 법률 정보 서비스”

### 우리가 해결하고자 한 핵심 질문

1. 법률 지식이 없는 사용자도 계약서의 주요 조건과 위험 조항을 이해할 수 있는가?
2. 계약 이후의 생활형 분쟁 질문에 관련 법령과 판례를 근거로 답할 수 있는가?
3. 민감한 계약서를 AI로 처리하면서 개인정보 노출 위험을 줄일 수 있는가?
4. 일회성 데모가 아니라 가입부터 분석, 상담, 이력 관리까지 이어지는 서비스 경험을 만들 수 있는가?

## 2. 주제 선정 배경

전·월세 계약은 임차인에게 큰 금액과 주거 안정이 걸린 거래다. 그러나 계약의 위험을 판단하는 데 필요한 정보는 계약서 특약, 등기부 권리관계, 법령, 판례, 분쟁 사례 등에 흩어져 있다. 특히 첫 독립을 준비하는 사회초년생은 어떤 항목을 확인해야 하는지조차 모른 채 계약을 진행할 수 있다.

계약 이후에도 문제는 이어진다. 보일러 수리 책임, 원상복구 범위, 계약 갱신, 보증금 반환처럼 생활에서 자주 발생하는 질문은 단순 검색만으로 자신의 상황에 맞는 답을 찾기 어렵다. 전문 상담은 정확하지만 시간과 비용에 대한 부담이 있어, 사용자가 초기 단계에서 빠르게 확인할 수 있는 1차 정보 도구가 필요하다고 판단했다.

| 문제 | 사용자 어려움 | HomeShield의 접근 |
| --- | --- | --- |
| 정보 비대칭 | 계약서·등기부·법률 용어를 해석하기 어려움 | 서류에서 주요 조건과 확인 항목을 구조화 |
| 계약 위험 확인 부족 | 위험 특약과 보증금 관련 신호를 놓칠 수 있음 | 위험 조항, 이유, 권장 조치를 리포트로 제공 |
| 분쟁 대응의 어려움 | 자신의 상황에 적용되는 법적 근거를 찾기 어려움 | 법령·판례·공공 자료를 검색해 상담 답변 생성 |
| 상담 접근 장벽 | 전문가 상담 전 기본 정보를 얻는 데 시간과 비용이 듦 | 일상어로 질문할 수 있는 AI 상담 제공 |
| 개인정보 노출 우려 | 계약서에 이름, 연락처, 계좌번호 등이 포함됨 | 외부 AI 처리 전에 개인정보 탐지·비식별화 |
| 서비스 흐름의 단절 | 분석 결과와 상담 내용을 다시 찾기 어려움 | 계정 기반 리포트·대화·알림 이력 관리 |

## 3. 제품 비전과 목표

### 3.1 제품 비전

> 임차인이 계약 전에는 놓치기 쉬운 위험을 확인하고, 계약 후에는 자신의 상황과 관련된 법적 근거와 다음 행동을 빠르게 찾을 수 있게 한다.

### 3.2 프로젝트 목표

| 목표 | 설명 |
| --- | --- |
| 계약서 이해 지원 | 법률 지식이 없어도 문서 업로드만으로 계약 유형, 금액, 기간, 특약과 위험 항목을 확인할 수 있게 한다. |
| 근거 기반 상담 | 임대차 관련 질문에 법령·판례·분쟁 사례·공공 가이드를 바탕으로 답변한다. |
| 개인정보 보호 | OCR 원문을 그대로 외부 LLM에 보내지 않고 비식별화된 텍스트만 분석에 사용한다. |
| 기다림이 보이는 분석 | 시간이 걸리는 OCR·AI 분석을 비동기로 처리하고 단계와 진행률을 사용자에게 보여준다. |
| 연결된 사용자 경험 | 회원가입, 문서 분석, 리포트, AI 상담, 알림, 마이페이지가 하나의 흐름으로 이어지게 한다. |
| 웹 서비스 고도화 | Streamlit 프로토타입을 React·FastAPI 기반의 클라이언트/서버 구조로 전환한다. |

### 3.3 제품 원칙

1. **근거를 먼저 보여준다.** 법률 관련 답변은 가능한 범위에서 법령·판례·공공 자료와 연결한다.
2. **모르는 내용은 추정하지 않는다.** 문서에서 확인되지 않은 금액·날짜·조항은 `미확인`으로 처리한다.
3. **개인정보를 먼저 보호한다.** 계약서 분석보다 개인정보 탐지와 비식별화를 먼저 수행한다.
4. **규칙과 AI의 역할을 나눈다.** 형식·용량·상태·패턴 검사는 코드가 담당하고, 비정형 조항 해석과 상담은 AI가 담당한다.
5. **위험과 행동을 함께 제시한다.** 위험 등급만 보여주지 않고 이유와 사용자가 확인할 다음 항목을 함께 안내한다.
6. **사용자의 데이터는 사용자에게만 보인다.** 분석, 대화, 알림은 인증된 소유자 범위에서만 조회·변경할 수 있다.

## 4. 대상 사용자

### Persona 1. 첫 전·월세 계약을 앞둔 사회초년생

- 계약서와 등기부등본을 처음 받아 어떤 내용을 확인해야 하는지 모른다.
- 특약이나 법률 용어를 검색해도 자신의 계약에 어떤 의미인지 판단하기 어렵다.
- 계약 전에 위험한 문구와 추가로 확인할 내용을 빠르게 알고 싶다.

### Persona 2. 계약 갱신·종료를 준비하는 임차인

- 갱신요구권, 퇴거, 원상복구, 보증금 반환 절차가 궁금하다.
- 자신의 상황과 관련된 법령이나 사례를 일상적인 질문으로 찾고 싶다.
- 이전에 분석한 계약서와 상담 내용을 다시 확인하고 싶다.

### Persona 3. 임대차 분쟁을 겪고 있는 임차인

- 수리 책임, 보증금 미반환, 계약 해지 등으로 임대인과 갈등 중이다.
- 전문가 상담 전에 쟁점과 준비해야 할 자료를 정리하고 싶다.
- AI의 결론만이 아니라 답변이 참고한 근거를 함께 확인하고 싶다.

### 핵심 사용자 과업

| 상황 | 사용자가 원하는 것 |
| --- | --- |
| 계약 전 | “서명하기 전에 이 계약서에서 위험하거나 빠진 부분을 확인하고 싶다.” |
| 계약 중 | “이 특약이 나에게 불리한지, 무엇을 추가로 확인해야 하는지 알고 싶다.” |
| 계약 후 | “보증금·수리·원상복구 문제에 적용되는 법적 근거와 대응 순서를 알고 싶다.” |
| 재방문 | “이전에 분석한 리포트와 상담 내용을 다시 보고 이어서 질문하고 싶다.” |

## 5. 3차 프로젝트에서 4차 프로젝트로의 고도화

우리 팀은 3차 프로젝트의 주제와 RAG 상담 구조를 그대로 복제하지 않고, 실제 서비스에서 필요한 사용자 흐름과 데이터 보호를 중심으로 다시 설계했다.

| 구분 | 3차 프로젝트 | 4차 HomeShield |
| --- | --- | --- |
| 서비스 형태 | Streamlit 기반 프로토타입 | React·Vite 웹 클라이언트와 FastAPI 서버 |
| 사용자 | 일회성 데모 사용자 | 이메일·카카오로 가입하는 계정 기반 사용자 |
| 데이터 저장 | 프로토타입 중심 저장 | Supabase PostgreSQL, pgvector, Storage |
| 문서 분석 | OCR 연동 중심 | 별도 OCR 워커, 개인정보 비식별화, 구조화 분석 |
| 처리 방식 | 요청 중심 처리 | PostgreSQL 작업 큐 기반 비동기 분석 |
| 분석 결과 | 기능 시연 중심 | 진행률, 위험 리포트, 분석 이력, 제목·삭제 관리 |
| AI 상담 | 기본 RAG 질의응답 | 대화방, 멀티턴 이력, 계약서 첨부, 질문 재작성 |
| 알림 | 별도 흐름 없음 | 분석 시작·완료·실패 알림과 브라우저 알림 |
| UI·UX | 단일 앱 화면 | 반응형 화면, 공통 오류·빈 상태·로딩 상태 |
| 배포 구조 | 로컬 데모 중심 | Docker Compose, Caddy, Nginx, AWS EC2 구성 |

이번 고도화의 핵심은 기술 스택을 바꾸는 데 있지 않았다. 사용자가 가입하고 문서를 올린 뒤, 분석이 끝날 때까지 기다리고, 결과를 다시 확인하며, 이어서 상담할 수 있는 전체 경험을 완성하는 데 초점을 맞췄다.

## 6. 제품 범위

### 6.1 이번 프로젝트에서 제공하는 기능

- 이메일 및 카카오 회원가입·로그인
- 필수 약관 동의와 회원 프로필 관리
- 임대차계약서·등기부등본·건축물대장 업로드 UI
- PDF, PNG, JPG, JPEG 다중 파일 검증
- OCR 기반 텍스트 추출과 개인정보 비식별화
- 비동기 계약서 분석과 단계·진행률 표시
- 계약 조건·특약·위험 요소·권장 조치 분석
- 종합 리스크 리포트와 분석 이력
- 법률·판례·공공 자료 기반 RAG 챗봇
- 채팅방·메시지 이력과 계약서 첨부
- 분석 상태 알림과 열린 브라우저 알림
- 프로필, 비밀번호, 최근 분석·대화, 알림 설정, 회원 탈퇴
- 이용약관, 개인정보처리방침, 법적 근거, FAQ 화면

### 6.2 이번 프로젝트에서 제외한 기능

- 인터넷등기소·정부24 문서의 실시간 조회와 진위 확인
- 실시간 시세·실거래가·전세가율·LTV 자동 계산
- 체납 여부와 보증보험 가입 가능 여부 확인
- 전자계약, 전입신고, 확정일자 신청 대행
- 변호사·법무사·공인중개사의 전문 자문 대체
- 결제, 구독, 프리미엄 회원 등급
- 관리자 콘솔과 상담원 연결
- 앱이 종료된 상태에서도 수신하는 Web Push

실시간 시세와 전세가율 진단은 3차 PRD에서 고도화 방향으로 제시했지만, 이번 프로젝트에서는 검증 가능한 API 연동보다 계약서 분석, 개인정보 보호, 사용자 이력과 서비스 구조 완성에 우선순위를 두었다.

## 7. 핵심 기능

### 7.1 회원가입과 로그인

사용자는 이메일 또는 카카오 계정으로 가입하고 로그인한다. 신규 사용자는 약관에 동의한 뒤 프로필을 생성하며, 로그인하지 않은 상태에서 계약 분석이나 채팅 화면에 접근하면 로그인 후 원래 화면으로 돌아간다.

주요 요구사항:

- 이메일·카카오 가입과 로그인 제공
- 가입 방식에 따른 회원 등록 상태 확인
- 필수 약관 동의 저장
- 로그인 세션 유지와 만료 처리
- 탈퇴 계정의 재접근 차단

### 7.2 계약서 업로드와 비동기 분석

사용자는 임대차계약서, 등기부등본, 건축물대장 슬롯에 파일을 추가한다. 파일은 PDF, PNG, JPG, JPEG 형식을 지원하며 파일당 최대 20MB, 한 번에 최대 10개까지 업로드할 수 있다.

분석 요청은 즉시 작업 ID를 반환하고 실제 OCR·AI 처리는 백그라운드에서 수행한다. 사용자는 업로드, OCR, 분석, 저장 단계와 진행률을 확인할 수 있다.

처리 흐름:

`파일 검증 -> 비공개 임시 저장 -> OCR -> 개인정보 비식별화 -> 안전성 재검사 -> AI 분석 -> 결과 저장 -> 원본 삭제`

### 7.3 개인정보 비식별화

계약서에는 이름, 주민등록번호, 전화번호, 이메일, 계좌번호 등 민감한 정보가 포함될 수 있다. OCR 워커는 문서에서 개인정보 패턴과 위치를 탐지하고, 외부 분석 모델에 전달할 텍스트를 플레이스홀더로 치환한다.

주요 요구사항:

- 원본 계약서와 원본 OCR 텍스트를 외부 LLM에 전달하지 않음
- 주민등록번호·전화번호·이메일·계좌번호 등 지원 패턴 탐지
- 비식별화 후 개인정보 패턴 재검사
- 안전하지 않은 결과는 자동 분석을 중단하거나 검토 필요 상태로 처리
- OCR 원문과 개인정보를 애플리케이션 로그에 기록하지 않음
- 작업 종료 후 임시 원본과 중간 파일 삭제

### 7.4 종합 리스크 리포트

분석이 완료되면 사용자는 계약서의 주요 내용을 한 화면에서 확인한다.

리포트 구성:

- 계약 유형, 보증금, 월세, 계약 기간
- 목적물 주소와 주택 유형
- 특약 사항
- 위험 항목별 심각도
- 위험 판단에 사용된 계약 문구
- 위험 이유와 권장 조치
- 종합 요약과 안전 점수
- 주소 기반 카카오 지도

사용자는 분석 리포트 목록을 다시 조회하고 제목을 변경하거나 삭제할 수 있다. 결과는 브라우저 인쇄 기능을 이용해 PDF로 저장할 수 있다.

### 7.5 AI 법률 상담

사용자는 보증금 반환, 계약 갱신, 수선 의무, 원상복구, 대항력과 우선변제권 등 전·월세 관련 질문을 일상어로 입력한다.

챗봇은 KURE-v1 임베딩과 PostgreSQL `pgvector`를 이용해 관련 법률 자료를 검색한다. 검색 결과의 관련성이 낮으면 법률 검색에 적합한 표현으로 질문을 한 번 재작성한 뒤 다시 검색한다. 답변은 법령·판례, 조정·상담 사례, 실무 참고 자료의 성격을 구분해 생성한다.

주요 요구사항:

- 대화방 생성·조회·이름 변경·삭제
- 이전 메시지를 반영하는 멀티턴 상담
- 법률 자료 검색과 근거 기반 답변
- 검색 관련성이 낮을 때 질의 재작성
- 계약서 신규 업로드와 대화방 첨부
- 첨부 계약서 내용과 법률 근거를 함께 고려한 답변
- 답변 실패 시 재생성
- Markdown, 목록, 표, 링크, 코드 블록 표시

### 7.6 알림

시스템은 회원가입과 분석 작업의 상태 변화를 알림으로 저장한다.

- 가입 환영 알림
- 분석 시작 알림
- 분석 완료 알림과 리포트 이동
- 분석 실패 알림
- 전체·읽지 않음 필터
- 선택·전체 읽음 처리
- 선택·전체 삭제
- 사용자가 허용한 경우 열린 브라우저에서 완료 알림 표시

### 7.7 마이페이지와 사용자 이력

사용자는 마이페이지에서 자신의 계정과 서비스 이용 이력을 관리한다.

- 이메일, 닉네임, 가입 방식, 프로필 이미지 확인
- 닉네임과 프로필 이미지 변경
- 최근 분석과 최근 대화 확인
- 이메일 계정 비밀번호 변경
- 브라우저 알림 설정
- 회원 탈퇴

### 시나리오 B. 계약 후 분쟁 상담

### 시나리오 C. 과거 결과 재확인

## 10. 데이터와 AI 설계

### 10.1 활용 데이터

우리 팀은 법률 원문만으로는 실제 임차인의 질문을 충분히 설명하기 어렵다고 판단해 법적 권위와 활용 목적이 다른 자료를 함께 구성했다.

| 데이터 | 활용 목적 |
| --- | --- |
| 주택임대차 관련 법령·법령해석례 | 권리와 의무에 대한 핵심 근거 |
| 전세사기·보증금·갱신·수선·중개 관련 판례 | 법원이 실제 사건을 판단한 기준 참고 |
| 임대차 분쟁조정·상담 사례집 | 생활형 분쟁과 유사 사례 설명 |
| 공공기관 가이드와 계약 체크리스트 | 사용자가 취할 수 있는 실무 행동 안내 |
| 사용자가 업로드한 계약서 | 계약 조건과 특약 분석, 첨부 문서 상담 |

### 10.2 RAG가 필요한 이유

전세가율과 같은 수치는 정해진 입력과 계산식이 있다면 코드로 계산할 수 있다. 반면 “집주인이 보증금을 돌려주지 않아요”, “이 특약이 유효한가요?” 같은 질문은 사용자의 상황과 관련 법령을 함께 해석해야 한다.

우리 팀은 정량적·규칙 기반 판단은 결정론적 코드가 담당하고, 정형화하기 어려운 계약 조항과 생활 분쟁 질문은 RAG가 담당하는 하이브리드 구조를 선택했다. 이를 통해 수치와 상태를 LLM이 임의로 생성하는 위험을 줄이고, AI는 검색된 근거를 설명하는 역할에 집중하게 했다.

### 10.3 근거의 권위 구분

- **구속적 근거**: 법령과 판례
- **설득적 근거**: 분쟁조정 사례와 상담 사례
- **참고 자료**: 공공기관 가이드와 표준계약서

답변은 사례를 법령과 같은 확정적 근거로 표현하지 않으며, 검색된 자료가 부족할 때는 확인 범위와 한계를 함께 안내한다.

### 10.4 AI 안전 원칙

- 계약서에 없는 금액·날짜·조항을 만들어내지 않는다.
- 검색 근거 밖의 법적 사실을 단정하지 않는다.
- 낮은 위험 또는 높은 안전 점수가 계약의 안전을 보장하지 않음을 안내한다.
- 계약 체결, 내용증명, 소송 등 중요한 의사결정 전에는 최신 공적 문서와 전문가 확인을 권장한다.
- 모델과 데이터의 품질은 Faithfulness, Context Precision·Recall, 응답 적합성으로 구분해 평가한다.

## 11. UX 요구사항

1. 법률 용어를 그대로 나열하기보다 사용자가 이해할 수 있는 문장으로 설명한다.
2. 로딩, 빈 결과, 오류, 재시도 상태를 모든 핵심 화면에서 일관되게 제공한다.
3. 위험 정보는 색상만으로 구분하지 않고 아이콘과 텍스트를 함께 사용한다.
4. 모바일에서도 계약서 업로드, 진행 상태, 리포트, 채팅을 사용할 수 있게 한다.
5. 분석 시간이 길어도 사용자가 현재 단계와 완료 여부를 알 수 있게 한다.
6. 삭제, 탈퇴처럼 되돌리기 어려운 행동은 확인 절차를 제공한다.
7. AI의 답변과 서비스의 법적 한계를 사용자가 쉽게 확인할 수 있게 한다.

| 검색 품질 | Context Precision / Recall | 각 0.85 이상 |
| 응답 속도 | AI 상담 응답 시간 p95 | 20초 이내 |
| 보안 | 타 사용자 분석·대화·알림 접근 성공 | 0건 |

목표 수치는 프로젝트 평가 기준이며 현재 달성치를 의미하지 않는다. 실제 평가 시 문서 유형, 질문 세트, 표본 수, 모델 버전을 함께 기록한다.

---

## 14. 제약사항과 향후 고도화

이번 프로젝트에서 핵심 사용자 흐름은 구현했지만, HomeShield가 실제 공개 서비스로 발전하려면 다음 항목을 추가로 보완해야 한다.

- 실제 한국어 계약서 표본을 이용한 개인정보 마스킹 성능 검증
- 리포트에서 비식별화 검토 필요 여부와 누락 정보 표시 강화
- 안전 점수의 계산 근거와 한계 설명
- 검색 근거가 없을 때 답변을 제한하는 안전장치
- 답변과 분리된 구조화 출처 카드와 출처 이력 저장
- 재현 가능한 법률 문서 색인·갱신 파이프라인
- 긴 첨부 계약서에서 질문 관련 조항을 찾는 문서 내부 검색
- 비밀번호 찾기, 분석 취소, 기존 리포트의 채팅 첨부
- 회원 탈퇴 후 보존 기간이 지난 데이터의 완전 삭제 자동화
- 실제 시세·실거래가·등기·건축물 데이터 연동
- 외부 서비스와 실제 브라우저를 포함한 E2E·보안 테스트

## 15. 기대 효과

### 사용자 가치

- 계약 전에 확인해야 할 위험과 누락 정보를 빠르게 파악할 수 있다.
- 계약 이후 분쟁 질문에 필요한 법적 근거를 일상어로 찾을 수 있다.
- 전문가 상담이 필요한 상황인지 판단하기 위한 1차 정보를 얻을 수 있다.
- 분석 결과와 상담 이력을 한 계정에서 다시 확인할 수 있다.

### 기술적 성과

- React와 FastAPI를 이용한 프런트엔드·백엔드 분리 구조
- Supabase Auth, PostgreSQL, pgvector, Storage를 연결한 서비스 데이터 구조
- PostgreSQL을 작업 큐로 활용한 비동기 OCR·AI 분석
- PaddleOCR-VL 기반 문서 인식과 개인정보 비식별화
- KURE-v1 임베딩과 LangGraph를 이용한 법률 RAG 챗봇
- 분석 상태 알림, 대화 이력, 사용자별 데이터 소유권 관리
- Docker Compose 기반 배포 구성과 자동화 테스트

### 프로젝트 고도화 성과

3차 프로젝트가 “전·월세 법률 정보를 RAG로 제공할 수 있는가”를 검증한 프로토타입이었다면, 4차 HomeShield는 “사용자가 가입하고 계약서를 안전하게 분석한 뒤 리포트와 상담을 계속 이용할 수 있는가”를 구현한 서비스 고도화 프로젝트다.
